# 루다피아 은밀한 살인 — 3D 맵 프로토타입 (구역 02)

ChatGPT 가 만든 좌표 데이터(`src/data/zone02_layout.json`)를 기준 레이아웃으로, 3D 저택(중앙 홀 · 동쪽 날개 · 현관 · 앞마당)을 구현한 개발 프로젝트.
기획서: Notion 「루다피아 은밀한 살인 기획서 v0.1」 / 에셋 요청서: [ChatGPT_에셋제작_요청서_v0.1.md](ChatGPT_에셋제작_요청서_v0.1.md)

## 실행

```bash
cd rudapia-murder-3d
npm install
npm run dev        # http://127.0.0.1:5174/
```

- `?q=low` : 저사양 모드 (그림자 해상도↓, MSAA·AO 끔, 해상도 배율 1)
- `legacy-greybox.html` : 처음 만든 임시 레이아웃 버전 (참고용)
- `swatch.html` : 절차적 재질 견본 확인 페이지

| 키 | 동작 |

**카메라:** 이동하면 카메라가 캐릭터 진행 방향 뒤로 빠르게 따라 돈다(`character.js` `follow`). 앞으로 갈 때는 약 0.2초에 정렬, 옆걸음은 완만하게, 후진은 돌지 않음. 마우스로 시점을 움직이는 동안(그리고 직후 0.45초)에는 자동 추적을 멈춘다.
| R | 현관으로 복귀 |

## 구조 (`src/zone02/`)

| 파일 | 역할 |
|---|---|
| `zones.js` | layout JSON 로드, 구역 판정(`zoneIdAt`), 방별 마감 스타일, 구역 인접 그래프 |
| `architecture.js` | 벽·창·문틀·몰딩·웨인스코팅·바닥·천장·지붕 (JSON 벽 좌표 기반) + 벽 충돌 등록 |
| `props.js`, `props/*.js` | 홀(원탁·샹들리에·대계단), 식당, 주방, 보안실, 기계실, 현관, 복도 소품 |
| `exterior.js` | 하늘·달·숲, 앞마당(분수·자동차·정문·토피어리), 외곽 길, 가로등, 경계 울타리 |
| `fx.js` | 달빛 줄기(가짜 볼류메트릭), 먼지 입자 |
| `materials.js`, `pbr.js`, `noise.js` | 절차적 PBR 재질(알베도+법선+거칠기) 생성 — **실제 텍스처로 교체될 자리** |
| `lights.js` | 조명 풀 (촛불·등불 수십 개 중 가까운 12개만 실제 광원) |
| `collide.js` | 원 vs 박스/원 충돌, 카메라 스프링암용 레이캐스트 |
| `character.js` | 임시 인물 모델(절차적 이족보행) + 어깨 너머 3인칭 카메라 |
| `batch.js` | 정적 메시 병합 (메시 약 2300개 → 약 500개) |
| `world.js`, `main.js` | 조립, 렌더러·후처리(GTAO·블룸·색보정), 입력, 루프 |

좌표: 단위 m, X=동, Z=남(북=-Z), 원점=홀 북서쪽 안쪽 모서리. 조명 구역은 `layout.zones` 의 id.

## ChatGPT 홀 이미지 적용 (`tools/make-hall-assets.mjs`)

`assets/ref/hall/` 의 ChatGPT 이미지 7장(원근 5 + 탑다운 2)에서 게임용 텍스처를 뽑아 `public/assets/zone02/` 에 만든다.
실행: `node tools/make-hall-assets.mjs` (sharp 필요: `npm install`)

| 입력 | 출력 | 용도 |
|---|---|---|
| `hall-top-full` 바닥 필드 | `hall_floor_albedo/rough/normal.png` | 홀 바닥 (C안: 바닥만 이미지). 박힌 조명 제거, 탁자·의자 영역은 단색 카펫으로 메움, 채도 낮춤 |
| 같은 이미지 남쪽 | `hall_runner_south.png` | 남쪽 문~현관 러너 |
| 원근 이미지 | `portrait_a/b/d/e.png`, `tapestry_a.png` | 초상화·태피스트리 (프레임 포함 크롭) |
| — | `hall_assets.json` | 바닥/러너 월드 배치(중심·크기). 기준: 원탁 중심=월드 (10,14), 27.6 px/m |

이미지가 없으면 `assets.js` 가 null 을 돌려주고 절차적 재질로 대체된다.
홀은 이미지에 맞춰 **천장 7m(2층 높이)** 로 상향 (`zones.js` 의 `HALL_H`). 필라스터·발코니·벨트 코스·태피스트리·흉상·2단 샹들리에·곡선 계단(러너)을 추가했다.

## 벽 정면 입면도 시트 (`tools/make-wall-sheets.mjs`)

ChatGPT 가 만든 **정면 입면도(투명 배경, 조명 없음)** 를 홀 벽면에 그대로 붙인다. 실행: `node tools/make-wall-sheets.mjs`

| 시트 | 원본 | 적용 |
|---|---|---|
| `wall_north` | `wall-north-elevation.webp` | 북쪽 벽(계단 뒤). 필라스터 중심선에서 잘라 3모듈(6.67m)을 20m 에 이음새 없이 이어붙임 |
| `wall_north_side` | 같은 이미지의 좌우 베이 | 남쪽 벽 좌우 보충 (서쪽은 좌우 반전) |
| `wall_east` (+ `wall_north_side_b`) | `wall-east-elevation.webp` | 동쪽 벽. 문 구멍 2개는 원본이 이미 투명. `marks`(문 중심)로 **문 간격 8m(z=5, 13)에 맞춰 가로를 압축**해 z≈3.5~14.5 에 놓고, 북쪽 3.5m 는 큰 초상화 베이, 남쪽 9.5m 는 보충 베이 2장으로 채움. 문 높이는 이미지의 문틀(3.57m)에 맞춰 3.55m |
| `wall_south` | `wall-south-elevation.webp` | 남쪽 벽 중앙(문 + 부채꼴 채광창 + 초상화 2). **문짝 영역은 알파로 잘라내** 통로를 열고, 문짝 2장(`door_leaf_a/b`)은 3D 평면으로 100° 열어 둠 |

**시트 규격 (다음 요청 기준):** 실루엣 높이 = 홀 벽 7m (약 126~162px/m), 좌우는 **필라스터 중심선에서 시작/끝**, 조명·그림자 없음, 투명 배경.
시트가 적용된 벽은 3D 창·몰딩·필라스터를 만들지 않는다 (`architecture.js` 의 `flatNorth/flatSouth`).


| wall_west | wall-west-elevation.webp | **서쪽 벽**. 열린 문틀 2개(z=5, 13)가 서재로 통한다. 영상 왼쪽 = 남쪽(z 큰 쪽), 문 간격 8m 에 맞춰 압축, 위아래 보충은 동쪽 벽과 동일 |

홀 4면 모두 이미지 시트로 완료.

**서쪽 별채(서재 2칸, 디자인 추가분)**: 서쪽 벽 문 2개 뒤에 8×9m 방 2개(서재 A: 책장·독서탁·안락의자 / 집무실 B: 책상·지구본·안락의자). zones.js 에서 layout 을 확장(벽·문·구역 추가), 책은 인스턴싱(props/library.js).

## 홀 바닥 (고화질 메달리온)

	ools/make-floor-hq.mjs: loor-medallion-hq.webp(1254², 탁자/카펫 없는 깨끗한 대리석)를 안쪽 원 반지름 3.9m 기준 약 86px/m, 14.6m 정사각으로 배치. 가장자리 0.9m 는 알파로 페더링해 바탕 대리석과 섞음. 카펫 원판·저해상도 바닥 이미지는 이 이미지가 있으면 쓰지 않는다. 남쪽 러너는 절차적(고해상도).

## 어두움/흐림 전수검사 (window.__dbg)

밤 모드가 기본이라 촛불이 닿지 않는 곳이 검게 뭉개지는 문제가 있었다. 맵 전체 보행 격자 x 8방향을 렌더해 **화면에서 거의 검은(밝기<9/255) 덩어리가 8% 이상**인 시점을 센다(바깥 12% 비네트 제외). 처음 1,110장 중 376장(34%)이 걸렸고, 아래 조치 후 **0장**.

| 조치 | 위치 |
|---|---|
| 밤 하늘/환경광/달빛/안개색 상향 | main.js NIGHT 프리셋, exterior.js 하늘 |
| 방·구역별 주변광(fill, 깜빡임 없음) | world.js FILL / FILL_OUT, 점광원 풀 22개 |
| 블랙 리프트(완전한 검정 방지) | main.js grade lift |
| AO 약화 | GTAO blendIntensity 0.7 |
| 카메라가 가로등/토피어리/화분/분수에 붙지 않게 | character.js camCircles |
| 과노출 방지(홀 조명/바닥 광택 낮춤) | props/hall.js |

## 선명도(흐릿함) 점검

`window.__dbg.audit()` (브라우저 콘솔) 이 장면의 모든 텍스처 표면에서 **월드 1m 당 텍스처 픽셀 수(px/m)** 를 낮은 순으로 보여준다. 가까이서 보기 좋은 기준은 대략 250px/m 이상.

| 대책 | 적용 |
|---|---|
| 디테일 레이어 (`detail.js`) | 저해상도 이미지(홀 바닥, 러너, 벽 입면도, 러그)에 1m 타일의 대리석 잔결/직물/석재 입자를 곱해 체감 선명도 보강. 바닥은 거칠기 맵으로 대리석/카펫을 자동 구분 |
| 오프라인 업스케일+샤프닝 | 바닥·러너 3배(약 83px/m), 문짝·초상화·벽 시트에 샤프닝 |
| 해상도 상향 | 복도 러너 46→252px/m, 식당 러그 127→253px/m, 콘크리트/잔디/석벽 텍스처 2배 |
| 카펫 원판 | 바닥 이미지에서 탁자·의자 영역을 단색으로 메운 부분을 고해상도 문양(256px/m)으로 덮음 |
| 렌더 해상도 | dpr 1 화면에서도 1.35배로 그림(수퍼샘플링), 이방성 필터 16 |

**한계:** 홀 바닥 이미지 원본이 27.6px/m 라 무늬 자체는 흐리다(디테일 레이어는 결을 더할 뿐 해상도를 만들어 내지 못함). 근본 해결은 **바닥 평면도를 4096px 이상으로 다시 받는 것**.

## 개발/검증용 훅 (`window.__dbg`)

`step(n)` 프레임 수동 진행(패널이 백그라운드면 rAF 가 멈춤), `teleport(x,z)`, `setNight(0|1)`, `info()`.
자동 검증 스크립트 예: 이동 루프 23개 경유지 통과, 무작위 이동 420회 맵 이탈 없음 (정문 철책 충돌 수정 후).
